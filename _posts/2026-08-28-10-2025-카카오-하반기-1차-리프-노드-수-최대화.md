루트 노드는 무조건 하나의 자식을 갖고 거기부터 분배노드냐 리프노드냐를 결정할 수 있는데 분배노드인 경우엔 2개 혹은 3개의 자식을 갖는다. 단, 같은 층위의 분배노드는 모두 같은 개수의 자식을 갖는다. 여기서 총 분배노드의 개수가 제한돼있고 리프노드들도 각자 자기보다 상위 층위에서의 자식 개수, 그러니까 2 혹은 3을 모두 곱해서 분배도 라는 값을 갖는데 이 분배도에도 제한이 있다. 그러니까 하고 싶다고 층위를 한참 내려갈 수 있는 게 아니다. 어차피 리프 노드 개수 세는 데 그럴 필욘 없지만. 그래서 가장 많은 leaf 노드 개수를 갖는 경우의 그 개수를 찾는 문제인데

처음 이걸 접했을 땐 binary tree도 아니고 3개짜리 tree를 어떻게 자료구조로  짜야 하나 고민돼서 바로 AI한테 물어봤다. 거기서 얻은 답은, 이건 실제로 tree를 그릴 필요가 없는 문제였다. 왜냐면 각각의 노드가 다르다고 해도 결국 생김새는 분배냐 아니냐의 차이일 뿐 모두 동일하기 때문이다. 게다가 살펴보면 굳이 분배 노드를 지금 쓸 수 있는데 아래 단계에서 쓸 이유가 없다. 왜냐면 상위에서 분배했을 수록 분배도를 낮게 가질 수 있기 때문. 또 분배노드를 최대한 적게 쓰면서 같은 개수의 리프 노드를 갖는 경우가 좋은데 2로 분배 후 3으로 분배하나, 3으로 분배 후 2로 분배하나 똑같이 6개의 리프노드지만(가능하면 전체가 분배하기로 했으니.) 결과적으로 2->3은 총 3개의 분배노드를, 3->2는 총 4개의 분배노드를 소비하므로 반드시 2개로 분배한 다음 3개로 분배하는 것이 이득이다. 그렇다면 문제는 2222233333...을 나열하는데 어느 시점에 2에서 3으로 변화시킬 것이냐, 하는 게 된다.  
여기까지 이야기를 듣고 난 다음 코딩은 쉬웠다. 

```java
class Solution {
    
    public int distLimit = 0;
    public int splitLimit = 0;
    public int bestAnswer = 0;
    
    public int solution(int dist_limit, int split_limit) {
        int answer = 0;
        
        distLimit = dist_limit;
        splitLimit = split_limit;
        
        search(0, 2, distLimit, 1, 1);
        answer = bestAnswer;
        
        return answer;
    }
    
    public void search(int prevLeaves, int prevSplit, int leftDist, int candidates, int splitScore){
        
        if(splitScore > splitLimit/2 || leftDist == 0){
            bestAnswer = Math.max(bestAnswer, prevLeaves + candidates);
            return;
        }
        
        int chosen = Math.min(leftDist, candidates);
        int nextPrevLeaves = prevLeaves + candidates - chosen;
        int nextLeftDist = leftDist - chosen;
        
        for(int split = prevSplit;split<=3;split++){
            if(splitScore <= splitLimit/split){
                search(nextPrevLeaves, split, nextLeftDist, chosen * split, splitScore * split);
            }
        }
    }
}
```

역시 손으로 case를 뜯어 살펴 본 다음 문제를 접해야겠다. 그 새 2~3문제 풀었다고 우쭐해져서 바로 문제로 달려든 게 독이 됐다. 이건 다른 이야기지만 claude로 개발하면서 터미널 쓰다 보니 ctrl+w로 앞 단어를 지우는 게 습관이 돼서 작성 중이던 페이지를 3번이나 껐다. 소요 시간은 이 글의 작성까지 총 1시간 가량. 다음엔 펜과 종이를 들고 문제 풀이를 시작해야겠다.
