오늘 바로 실행할 수 있는 **Day 1 상세 타임라인 및 작업 체크리스트**입니다. 하루 일과인 **09:00 ~ 17:00 (점심시간 12:00~13:00 포함, 총 7시간)** 일정에 맞춰 바로 착수하세요.

---

### 09:00 ~ 10:00 (1시간) | [트랙 A] 코딩테스트 환경 구축 및 진단

목표: 코딩테스트 루틴을 시스템화하고 내 현재 위치를 객관적으로 측정합니다.

1. **플랫폼 세팅**
* 프로그래머스 / 백준 / LeetCode 중 주력 플랫폼 1~2개 선택 후 로그인.
* 개발 환경(IDE 및 로컬 실행 환경) 세팅.


2. **진단 문제 2개 풀이 (각 25분 제한)**
* **1번:** 프로그래머스 Lv.2 / 백준 실버 3~4 수준의 **구현/문자열/해시** 문제 1개.
* **2번:** 프로그래머스 Lv.2 / 백준 실버 1~2 수준의 **BFS/DFS 또는 그리디** 문제 1개.


3. **진단 결과 기록**
* 풀이 성공 여부, 소요 시간, 막힌 구간을 노트에 기록합니다. (오늘부터 매일 아침 9시는 코테 고정입니다.)



---

### 10:00 ~ 12:00 (2시간) | [트랙 B] AI 개발 환경 구축 & Agent Skills 정독

목표: Claude Max 환경을 설정하고, 차장님이 강조한 Agent Skills의 동작 메커니즘을 완벽히 이해합니다.

1. **Claude Max 결제 및 Claude Code CLI 세팅 (30분)**
* Claude Max 플랜($100/월) 결제 진행.
* 터미널에서 Claude Code CLI 설치 및 인증:
```bash
npm install -g @anthropic-ai/claude-code
claude

```




2. **Agent Skills 공식 문서 정독 (1시간)**
* 공식 문서(`[https://docs.claude.com/en/docs/claude-code/overview](https://docs.claude.com/en/docs/claude-code/overview)`)를 정독하며 다음 요소를 파악합니다:
* **전역 Skill 위치:** `~/.claude/skills/` (개인 워크플로용)
* **프로젝트 Skill 위치:** `<project-root>/.claude/skills/` (팀/프로젝트 전용)
* **Skill 작성 구조:** YAML Frontmatter (`name`, `description`) + 마크다운 본문 규칙.




3. **글로벌 기본 Skill 1개 테스트 구상 (30분)**
* `~/.claude/skills/commit-convention/SKILL.md`를 만들어 단순 Git 커밋 메시지 규칙(Conventional Commits)을 강제하는 기본 스킬을 로컬에 작성해봅니다.

### 13:00 ~ 15:00 (2시간) | [트랙 B] `butter me up` 요구사항 & 시나리오 논의 (Claude 세션)

목표: 프로젝트 범위를 최소 코어 루프(Core Loop)로 잔인하게 줄이고, AI와 함께 유스케이스 및 비기능 요구사항을 도출합니다.

1. **Claude 세션 오픈 (Sonnet 또는 Opus 모델 사용)**
* 아래 프롬프트를 복사해서 Claude에게 입력하고 논의를 시작합니다:


> **[Prompt]**  
> "나는 자기계발 서비스 `butter me up`을 포트폴리오용으로 개발하려고 해. 이 프로젝트의 핵심 목적은 단순 앱 구현이 아니라 **2026년 기준의 AI 페어코딩 워크플로, 클라우드 오토스케일링(K8s/HPA), 보안(OWASP Top 10), 높은 수준의 아키텍처 역량**을 증명하는 거야.  
> 1. 기능 범위를 가장 명확한 코어 루프(예: 목표 설정 -> 일상 기록 -> Claude API 기반 AI 코칭 피드백) 1개로 줄여줘.  
> 2. 사용자 핵심 유스케이스(Use Cases) 3~5가지를 정의해줘.  
> 3. 시스템의 비기능 요구사항(부하테스트 목표, 보안 체크리스트, AI API 스트리밍 및 에러 처리)을 명시해줘."
> 
> 


2. **결과 검토 및 시나리오 정의권 확보**
* AI가 제안한 요구사항 중 불필요한 기능은 모조리 쳐냅니다.
* 테스트에서 AI가 편법을 쓰지 못하도록 **'인간이 직접 소유할 유스케이스 시나리오 문서'** 목록을 확정합니다.

### 15:00 ~ 17:00 (2시간) | [트랙 B] Git 저장소 생성 & Day 1 산출물 커밋

목표: 첫 날의 논의 결과를 코드베이스 문서와 Agent Skills로 변환하여 Git 저장소에 커밋합니다.

1. **Git 저장소 생성 및 초기화 (15분)**
```bash
mkdir butter-me-up
cd butter-me-up
git init
mkdir -p docs/architecture .claude/skills

```


2. **Day 1 핵심 문서 3종 작성 (1시간 15분)**
* **`README.md`**: 프로젝트 소개 + "AI Agent Skills 기반 개발 워크플로" 명시.
* **`docs/requirements.md`**: 13:00~15:00 세션에서 확정한 코어 유스케이스 및 비기능 요구사항 기록.
* **`docs/architecture/ADR-001-tech-stack.md`**: 기술 스택 및 아키텍처 결정 기록(ADR) 작성.
* 예시 내용: 왜 이 언어/프레임워크를 택했는가, 로컬 K8s(kind/k3d) 환경 도입 배경 등.




3. **프로젝트 전용 첫 Agent Skill 작성 (30분)**
* `.claude/skills/code-style/SKILL.md` 생성 및 커밋:
```markdown
---
name: code-style
description: 프로젝트 전용 코딩 스타일 및 규칙을 강제합니다.
---
# 코딩 스타일 및 작성 규칙

1. 모든 비즈니스 로직은 단단한 단위 테스트(Unit Test)를 명시적으로 작성해야 합니다.
2. AI 에이전트는 구현 작업 중 기존 테스트 코드를 임의로 수정하거나 삭제해서는 안 됩니다.
3. 예외 처리는 글로벌 에러 핸들러로 위임하며, 커스텀 예외 클래스를 사용합니다.

```




4. **Day 1 첫 커밋 & 푸시 (10분)**
```bash
git add .
git commit -m "docs: 프로젝트 뼈대 구축, 요구사항 정의 및 ADR-001 작성"

```
