컨테이너 창고의 상태 n*m이 주어지고 항상 대문자 알파벳 하나씩으로 가득 찬 상태이다. 반출 요청 목록 requests가 오는데 대문자 알파벳 2글자이거나 1글자이다. 1글자이면 외부에 노출된(4면 중 하나가 노출된 상태) 컨테이너 중 해당 알파벳을 모두 배출하고 2글자이면 크레인을 사용해 외부로 노출되지 않은 컨테이너까지 모두 제거한다.

문제를 보자마자 상태 관리(노출됨, 비어있음, 들어있음)를 하고 요청이 종료될 때마다 상태를 갱신해주면 된다고 생각했다. 풀이 중 상태 값은  
-1: 비어있으며 상태 관리 완료  
0: 비어있으며 상태 관리 안 됨  
1: 들어있지만 노출 안 됨  
2: 들어있으며 노출됨  
의 4가지로 관리됐다. 방금 이 글을 작성하면서 깨달은 건데 -1로 박아두면 나중에 다시 관리할 필요가 없었을지 생각을 안 했다. 다만 생각해보니 한 번 계산을 통해 -1로 확정된 칸은 다시 계산할 필요가 없다. 상태 업데이트가 일어나는 원인은 오직 0, 1, 2 상태였던 칸에서만 발생하며 그것이 -1로 전파될 이유가 없기 때문이다. 하지만 다음에 비슷한 문제를 풀이할 때는 이런 것들도 좀 더 염두에 둬야겠다.

```java
import java.util.Queue;
import java.util.LinkedList;

class Solution {
    
    // 0: empty
    // 1: cannot reach
    // 2: reachable
    public int[][] state;
    public int n;
    public int m;
    
    public Queue<int[]> queue = new LinkedList();
    
    public int solution(String[] storage, String[] requests) {
        int answer = 0;
        
        n = storage.length;
        m = storage[0].length();
        state = new int[n][m];
        
        for(int i=0;i<n;i++) for(int j=0;j<m;j++) {
            if(i == 0 || j == 0 || i == n-1 || j == m-1) state[i][j] = 2;
            else state[i][j] = 1;
        }
        
        int asked = requests.length;
        for(int t = 0;t<asked;t++){
            String req = requests[t];
            boolean crane = req.length() == 2;
            char container = req.charAt(0);
            
            if(crane){
                for(int i=0;i<n;i++){
                    for(int j=0;j<m;j++){
                        if(storage[i].charAt(j) != container) continue;
                        if(state[i][j] <= 0 ) continue;
                        
                        if(state[i][j] == 1) state[i][j] = 0;
                        if(state[i][j] == 2){
                            state[i][j] = -1;
                            queue.offer(new int[]{i,j});
                        }
                        
                    }
                }
            } else {
                // not crane
                for(int i=0;i<n;i++){
                    for(int j=0;j<m;j++){
                        if(storage[i].charAt(j) != container) continue;
                        if(state[i][j] == 2){
                            state[i][j] = -1;
                            queue.offer(new int[]{i,j});
                        }
                    }
                }
            }
            reachableCheck();
        }
        
        for(int i=0;i<n;i++)for(int j=0;j<m;j++) answer += (state[i][j] + 1)/2;
        
        return answer;
    }
    
    public void reachableCheck(){
        while(!queue.isEmpty()){
            int[] point = queue.poll();
            int i = point[0];
            int j = point[1];
            for(int[] around : new int[][]{new int[]{i+1, j},
                                            new int[]{i, j+1},
                                            new int[]{i-1, j},
                                            new int[]{i, j-1}}){
                if(0 > around[0] || around[0] >= n ||
                  0 > around[1]  || around[1] >= m) continue;
                if(state[around[0]][around[1]] <= 0){
                    if(state[around[0]][around[1]] != -1){
                        queue.offer(new int[]{around[0],around[1]});
                        state[around[0]][around[1]] = -1;
                    }
                    continue;
                }
                state[around[0]][around[1]] = 2;
            }
        }
    }
}
```

코딩 중 java.util.Queue와 java.util.LinkedList 에서 특히 java Queue의 사용법에 대해 검색 도움을 좀 받았다. 또한 check()함수에서 0인 칸이 인접한 0을 호출하고, 다시 0이된 칸이 인접한 0을 다시 호출하는 순환 호출에 대해 생각지못해 -1을 추가했다. 이 또한 처음에는 boolean 값의 배열을 새로 두었다가 -1로 상태 관리가 가능하겠다는 판단(answer의 덧셈 식을 고치고 싶지 않았다.)으로 state 배열과 알고리즘의 일부 조건을 수정했다.
