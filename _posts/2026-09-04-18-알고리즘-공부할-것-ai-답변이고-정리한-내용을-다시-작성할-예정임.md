# 1. 유니온 파인드 (Disjoint Set Union)

## 언제

"이 둘이 같은 그룹인가?"와 "이 둘을 같은 그룹으로 합쳐라"만 반복되는 상황입니다. 그룹의 **내부 구조는 필요 없고 소속만** 알면 될 때 씁니다.

- 연결 요소(컴포넌트) 개수 세기
- 사이클 존재 여부 판정
- 최소 신장 트리(크루스칼)
- 네트워크 연결 여부

## 핵심 개념

각 그룹을 트리로 표현하고, **루트 정점을 그룹의 이름**으로 씁니다. 그래프를 실제로 만들지 않아도 되는 게 핵심입니다. 도넛 문제가 정확히 이 경우였습니다.

두 가지 최적화가 붙어야 실전에서 씁니다. 경로 압축(찾으면서 부모를 루트로 당겨놓기)과 union by size(작은 트리를 큰 트리에 붙이기)입니다.

## 코드

```java
class DSU {
    int[] parent, size;

    DSU(int n) {
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }

    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];   // 경로 압축
            x = parent[x];
        }
        return x;
    }

    boolean union(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;            // 이미 같은 그룹 = 사이클
        if (size[a] < size[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        size[a] += size[b];
        return true;
    }
}
```

`union`의 반환값이 `false`면 그 간선은 사이클을 만든다는 뜻이라, 크루스칼에서 그대로 활용됩니다.

## 문제 신호

"연결되어 있다", "같은 그룹", "합친다", 간선이 순서 없이 주어짐. 그래프 탐색(BFS/DFS)으로도 풀리지만, **간선이 하나씩 추가되는 상황**이면 유니온 파인드가 압도적으로 유리합니다.

# 2. 다익스트라

## 언제

가중치가 있는 그래프에서 **한 정점에서 나머지 전부로의 최단 거리**를 구할 때. 음수 간선이 없어야 합니다.

BFS는 모든 간선의 비용이 같을 때만 최단 경로를 보장합니다. 비용이 다르면 다익스트라입니다.

## 핵심 개념

"아직 확정되지 않은 정점 중 거리가 가장 짧은 것부터 확정한다"는 그리디입니다. 우선순위 큐에서 꺼낸 정점의 거리는 이미 최소값이므로 다시 볼 필요가 없습니다.

## 코드

```java
import java.util.*;

int[] dijkstra(List<int[]>[] graph, int start, int n) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[start] = 0;

    // {정점, 거리}
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
    pq.offer(new int[]{start, 0});

    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int u = cur[0], d = cur[1];
        if (d > dist[u]) continue;           // 낡은 항목이면 버림

        for (int[] e : graph[u]) {           // e = {도착정점, 가중치}
            int v = e[0], w = e[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{v, dist[v]});
            }
        }
    }
    return dist;
}
```

`if (d > dist[u]) continue;` 이 한 줄이 방문 배열 역할을 합니다. 이걸 빼면 같은 정점을 여러 번 처리해서 느려집니다.

인접 리스트는 이렇게 만듭니다.

```java
List<int[]>[] graph = new List[n];
for (int i = 0; i < n; i++) graph[i] = new ArrayList<>();
for (int[] e : edges) graph[e[0]].add(new int[]{e[1], e[2]});
```

## 문제 신호

"최소 비용", "가장 빠른 경로", 간선마다 다른 시간/요금. 거리 합이 크면 `long`을 씁니다(오버플로 단골).

# 3. 위상 정렬

## 언제

**선후 관계가 있는 작업들의 순서**를 정할 때. 사이클이 없는 방향 그래프(DAG)에서만 됩니다.

- 선수과목 이수 순서
- 빌드 의존성
- 작업 스케줄링
- "A가 B보다 먼저" 형태의 조건들

## 핵심 개념

진입 차수(들어오는 간선 수)가 0인 정점은 지금 당장 처리할 수 있습니다. 그걸 처리하고 나가는 간선을 제거하면, 새로 진입 차수 0이 되는 정점이 생깁니다. 이 반복입니다.

도넛 문제에서 쓴 진입/진출 차수 아이디어와 같은 도구를 씁니다.

## 코드

```java
List<Integer> topoSort(List<Integer>[] graph, int[] indegree, int n) {
    Deque<Integer> queue = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indegree[i] == 0) queue.offer(i);

    List<Integer> order = new ArrayList<>();
    while (!queue.isEmpty()) {
        int u = queue.poll();
        order.add(u);
        for (int v : graph[u]) {
            if (--indegree[v] == 0) queue.offer(v);
        }
    }
    // order.size() < n 이면 사이클이 존재
    return order;
}
```

부산물이 유용합니다. `order.size()`가 `n`보다 작으면 **사이클이 있다**는 뜻이라, 사이클 판정에도 씁니다.

## 문제 신호

"먼저 해야 한다", "~ 다음에", "의존한다", "가능한 순서가 존재하는가". 최소 단계 수를 물으면 큐를 레벨 단위로 돌려서 깊이를 셉니다.

# 4. 누적합

## 언제

배열의 **구간 합을 여러 번 물어볼 때**. 매번 더하면 질의당 O(n)인데, 미리 한 번 전처리하면 질의당 O(1)이 됩니다.

## 핵심 개념

`prefix[i] = arr[0] + ... + arr[i-1]`을 미리 계산해두면, 구간 [l, r]의 합은 뺄셈 한 번입니다.

```java
int[] prefix = new int[n + 1];
for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + arr[i];

// [l, r] 구간 합 (0-indexed, 양끝 포함)
int sum = prefix[r + 1] - prefix[l];
```

인덱스를 1칸 밀어놓는 게 요령입니다. `l = 0`일 때 예외 처리가 필요 없어집니다.

## 2차원 버전

```java
int[][] p = new int[n + 1][m + 1];
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)
        p[i+1][j+1] = grid[i][j] + p[i][j+1] + p[i+1][j] - p[i][j];

// (r1,c1) ~ (r2,c2) 직사각형 합
int sum = p[r2+1][c2+1] - p[r1][c2+1] - p[r2+1][c1] + p[r1][c1];
```

겹치는 부분을 두 번 뺐으니 한 번 더해주는 포함-배제입니다.

## 차분 배열 (역발상)

**구간에 일괄로 더하는 연산이 많고 최종 결과만 필요할 때** 쓰는 반대 기법입니다.

```java
int[] diff = new int[n + 1];
// [l, r]에 v를 더하는 연산
diff[l] += v;
diff[r + 1] -= v;

// 모든 연산 후 한 번에 복원
int[] result = new int[n];
int acc = 0;
for (int i = 0; i < n; i++) { acc += diff[i]; result[i] = acc; }
```

서버 증설 문제에서 `for(int i=hour;i<hour+k;i++)`로 k칸을 매번 돌렸는데, 이 문제는 k와 시간이 작아서 통과했지만 범위가 컸으면 차분 배열이 정답입니다. 시작에 +, 끝+1에 −를 찍고 마지막에 한 번 누적하면 됩니다.

## 문제 신호

"구간의 합", "부분합", 질의가 여러 개, 구간 일괄 업데이트.

# 5. 투 포인터 / 슬라이딩 윈도우

## 언제

**연속된 구간**을 다루는데, 구간의 시작과 끝이 둘 다 한 방향으로만 움직일 때. O(n²) 완전탐색을 O(n)으로 줄입니다.

## 핵심 개념

오른쪽 포인터를 늘려서 조건을 깨뜨리고, 왼쪽 포인터를 당겨서 조건을 회복합니다. 두 포인터가 뒤로 가지 않으므로 전체 이동이 2n번입니다.

**단조성**이 조건입니다. 구간을 늘리면 값이 커지기만 하고, 줄이면 작아지기만 해야 합니다. 음수가 섞이면 못 씁니다.

## 코드

합이 target 이하인 최장 구간:

```java
int longest(int[] arr, int target) {
    int left = 0, sum = 0, best = 0;
    for (int right = 0; right < arr.length; right++) {
        sum += arr[right];
        while (sum > target) {            // 조건 회복
            sum -= arr[left];
            left++;
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

정렬된 배열에서 합이 target인 쌍 찾기(양끝에서 좁히는 형태):

```java
int l = 0, r = arr.length - 1;
while (l < r) {
    int sum = arr[l] + arr[r];
    if (sum == target) return new int[]{l, r};
    if (sum < target) l++;
    else r--;
}
```

## 문제 신호

"연속된", "부분 배열", "최대 길이", "조건을 만족하는 최소 구간". **정렬된 배열에서 두 수를 찾는 것**도 이 계열입니다.

# 6. 비트마스킹 DP

## 언제

**집합의 상태**를 DP의 키로 써야 하는데, 원소가 20개 이하일 때. 부분집합이 2^n개라 n이 20이면 백만, 25면 3300만이라 이 근처가 한계입니다.

- 외판원 순회(TSP)
- "모든 작업을 배정하는 최소 비용"
- "방문한 도시 집합"이 상태에 필요한 경우

## 핵심 개념

집합을 정수 하나로 표현합니다. `1011`(2진수)이면 0, 1, 3번 원소가 포함된 상태입니다.

```java
mask | (1 << i)        // i번 추가
mask & (1 << i)        // i번 포함 여부 (0이 아니면 포함)
mask & ~(1 << i)       // i번 제거
Integer.bitCount(mask) // 원소 개수
(1 << n) - 1           // 전체 집합
```

## 코드 (TSP)

`dp[mask][i]` = 방문한 집합이 mask이고 현재 i번에 있을 때의 최소 비용.

```java
int tsp(int[][] cost, int n) {
    int FULL = (1 << n) - 1;
    int INF = Integer.MAX_VALUE / 2;
    int[][] dp = new int[1 << n][n];
    for (int[] row : dp) Arrays.fill(row, INF);
    dp[1][0] = 0;                          // 0번에서 출발

    for (int mask = 1; mask <= FULL; mask++) {
        for (int i = 0; i < n; i++) {
            if ((mask & (1 << i)) == 0) continue;   // i가 mask에 없으면 스킵
            if (dp[mask][i] == INF) continue;

            for (int j = 0; j < n; j++) {
                if ((mask & (1 << j)) != 0) continue;  // 이미 방문
                int next = mask | (1 << j);
                dp[next][j] = Math.min(dp[next][j], dp[mask][i] + cost[i][j]);
            }
        }
    }

    int ans = INF;
    for (int i = 1; i < n; i++) ans = Math.min(ans, dp[FULL][i] + cost[i][0]);
    return ans;
}
```

## 문제 신호

**n ≤ 20** 이 가장 강한 신호입니다. 제약이 유독 작으면 지수 시간을 허용한다는 뜻입니다. 거기에 "모든 ~를 방문/배정/선택" + "순서나 조합에 따라 비용이 다름"이 붙으면 거의 확정입니다.

완전범죄에서 쓰신 "상태를 정의하고 최선값만 갱신한다"는 사고가 그대로 적용됩니다. 다만 상태가 정수 하나가 아니라 집합일 뿐입니다.

# 7. 세그먼트 트리 (선택)

## 언제

**구간 질의와 점 갱신이 둘 다 자주 일어날 때**. 누적합은 갱신이 없을 때만 유효한데, 값이 바뀌면 매번 전체를 다시 계산해야 합니다. 세그먼트 트리는 둘 다 O(log n)입니다.

| | 구간 질의 | 값 변경 |
|---|---|---|
| 그냥 배열 | O(n) | O(1) |
| 누적합 | O(1) | O(n) |
| 세그먼트 트리 | O(log n) | O(log n) |

## 핵심 개념

배열을 반씩 쪼개서 트리로 만들고, 각 노드가 자기 구간의 합(또는 최소/최대)을 들고 있습니다. 질의 구간은 최대 O(log n)개의 노드로 덮이고, 값 하나가 바뀌면 그 조상들만 갱신하면 됩니다.

## 코드

```java
class SegTree {
    int n;
    long[] tree;

    SegTree(int[] arr) {
        n = arr.length;
        tree = new long[4 * n];
        build(arr, 1, 0, n - 1);
    }

    void build(int[] arr, int node, int s, int e) {
        if (s == e) { tree[node] = arr[s]; return; }
        int mid = (s + e) / 2;
        build(arr, node * 2, s, mid);
        build(arr, node * 2 + 1, mid + 1, e);
        tree[node] = tree[node * 2] + tree[node * 2 + 1];
    }

    void update(int node, int s, int e, int idx, int val) {
        if (s == e) { tree[node] = val; return; }
        int mid = (s + e) / 2;
        if (idx <= mid) update(node * 2, s, mid, idx, val);
        else update(node * 2 + 1, mid + 1, e, idx, val);
        tree[node] = tree[node * 2] + tree[node * 2 + 1];
    }

    long query(int node, int s, int e, int l, int r) {
        if (r < s || e < l) return 0;              // 완전히 벗어남
        if (l <= s && e <= r) return tree[node];   // 완전히 포함
        int mid = (s + e) / 2;
        return query(node * 2, s, mid, l, r)
             + query(node * 2 + 1, mid + 1, e, l, r);
    }

    // 외부에서 부를 때
    void update(int idx, int val) { update(1, 0, n - 1, idx, val); }
    long query(int l, int r) { return query(1, 0, n - 1, l, r); }
}
```

합 대신 `Math.min`을 쓰면 구간 최솟값 트리가 됩니다. 구조는 같습니다.

## 문제 신호

"값이 바뀐다" + "구간을 물어본다"가 동시에 나오고, n과 질의 수가 둘 다 10만 이상. 코딩테스트 출제 빈도는 앞의 것들보다 낮으니 **나머지를 다 익힌 뒤에** 손대셔도 됩니다.

# 판별표

문제를 봤을 때 이 순서로 훑으면 대부분 걸립니다.

| 보이는 것 | 떠올릴 것 |
|---|---|
| 간선이 하나씩 추가, "같은 그룹" | 유니온 파인드 |
| 가중치 있는 최단 경로 | 다익스트라 |
| 가중치 없는 최단 경로 | BFS |
| "A 다음에 B", 의존 관계 | 위상 정렬 |
| 구간 합 질의 여러 번, 갱신 없음 | 누적합 |
| 구간에 일괄 더하기, 결과만 필요 | 차분 배열 |
| 연속 구간 + 단조 조건 | 투 포인터 |
| n ≤ 20, 집합이 상태 | 비트마스킹 DP |
| 구간 질의 + 잦은 갱신 | 세그먼트 트리 |
| 답을 정하면 판정이 쉬움 | 이분 탐색 (매개변수 탐색) |

마지막 줄은 이미 퍼즐 게임에서 쓰신 것입니다.

## 학습 순서 제안

누적합과 투 포인터는 개념이 가벼우면서 출제 빈도가 높으니 먼저 잡으시면 좋습니다. 그다음 유니온 파인드(오늘 절반은 이해하신 상태), 위상 정렬, 다익스트라 순으로 가고, 비트마스킹 DP는 완전범죄에서 보여주신 상태 DP 감각이 있으니 생각보다 빨리 붙을 겁니다. 세그먼트 트리는 마지막입니다.

각각 백준 기준으로 대표 문제를 하나씩만 풀어보셔도 템플릿이 손에 남습니다. 필요하시면 유형별 추천 문제도 뽑아드리겠습니다.
