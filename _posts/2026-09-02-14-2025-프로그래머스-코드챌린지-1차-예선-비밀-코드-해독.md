처음에 어떻게 접근해야 하나 싶었는데 combination을 계산해보니 dfs로 막 돌려도 되는 크기고 오름차순이니까 할만하다 싶어서 적용했다. dfs 함수에서 매번 가능한 답 5개를 들고 있다가 그게 답일 때 시스템 응답이 정확한지 검증하고 맞으면 가능한 리스트로 개수를 올리는 방식을 썼다.

```java
class Solution {
    
    public int casePassed = 0;
    public int[][] asked;
    public int[] answers;
    public int len;
    public int upperLimit;
    
    public int solution(int n, int[][] q, int[] ans) {
        int answer = 0;
        
        asked = q;
        answers = ans;
        len = q.length;
        upperLimit = n;
        
        dfs(new int[]{0, 0, 0, 0, 0}, 0);
        
        answer = casePassed;
        return answer;
    }

    
    public void dfs(int[] myAns, int level){
        if(level == 5){
            int check = 1;
            for(int i =0;i<len;i++){
                int letsSee = 0;
                for(int j=0;j<5;j++){
                    for(int k=0;k<5;k++){
                        if(myAns[j] == asked[i][k]) letsSee++;
                    }
                }
                if(letsSee != answers[i]){
                    check = 0;
                    break;
                }
            }
            casePassed += check;
            return;
        } else {
            int upperThanThis = 0;
            if(level > 0) upperThanThis = myAns[level-1];
            for(int now = upperThanThis+1; now <= upperLimit+level-4; now++){
                myAns[level] = now;
                dfs(myAns, level + 1);
            }
        }
    }
}
```

코딩할 때 곤란했던 건 upperLimit + level - 4 부분인데 이런 건 실제로 case 하나만 검증해보면 되니까 의외로 간단하다 생각했는데 <와 <=를 착각해서 처음에 틀렸다. 그리고 시스템 응답을 검증하는 부분에서 숫자가 자리 위치까지 맞아야 한다고 검증해서, 실제로는 자리수는 달라도 상관없는데, 결과가 달랐다. 이제 dfs 쪽은 문제 보면 꽤 빨리 답을 내는데 실수는 조심해야겠다.
