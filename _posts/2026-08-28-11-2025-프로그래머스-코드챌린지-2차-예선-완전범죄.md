물건 개수만큼 각 물건을 A혹은 B가 훔쳤을 때의 흔적 개수가 담겨있는 int info[][]가 주어진다. A는 흔적을 n개 이상, B는 m개 이상 남기면 안되며 가능한 A의 흔적을 적게 하고 싶을 때 A의 흔적 개수를 찾는 문제이다. 불가능한 경우는 -1.  
그냥 dfs로 풀 수 있을 줄 알았는데 시간 복잡도를 너무 많이 쓴다. 1번부터 마지막까지 차례로 훔친다고 봤을 때 각 단계에서 A의 흔적이 적은 게 유리하므로 물건을 하나씩 훔칠 때마다 A의 흔적별로 가장 적은 B의 흔적인 경우를 기록한다. 그러니까 이 물건을 A가, 혹은 B가 훔쳤을 때 이전 기록과 대조해서 도달 가능한 최선의 상태를 찾는 과정이다. 각 물건을 훔치는 경우를 for문으로 순회하고는 있지만 사실상 독립적인 사건으로 보며 states를 통해 전체 장부만 관리하는 셈. 최선의 상태란, 예를 들어 물건 0이 각각 1, 5이고 물건 1은 1, 1일 때 차례로 B, A가 훔치면 흔적이 1, 5로 남고 A, B로 훔치면 1, 1로 남는다. 이걸 A의 흔적 개수 기준으로 보고 B의 흔적이 가장 적은 순간을 맞추는 셈이다.  
그래서 지금 A의 흔적 개수가 몇이든 상관없이(그러니까 몇 번째 물건을 훔치고 있는지는 관계없다. 지금이 어떤 상황이든 이 물건을 A가 훔치거나 B가 훔치면 도달 가능한 최선인가를 보는 것이다. 다만 for문으로 순회하므로 앞선 물건에 대한 최선의 정보가 장부에 계속 누적된다. 사실상 '지금'이라는 게 없는 셈) 이 물건을 누가 훔치느냐에 따른 최적 상태를 min으로 업데이트 하며 최종적으로는 가능한 a의 최소값을 찾는 것이다. 


```java
class Solution {
    
    
    public int solution(int[][] info, int n, int m) {
        int answer = n;
        int stuffs = info.length;
        
        int[] states = new int[n];
        for(int i=0;i<n;i++) states[i] = m;
        states[0] = 0;
        for(int stuff=0;stuff<stuffs;stuff++){
            
            int stainA = info[stuff][0];
            int stainB = info[stuff][1];
            
            int[] nextStates = new int[n];
            
            for(int i=0;i<n;i++) nextStates[i] = m;
            
            for(int a=0; a<n;a++){
                if(states[a]>=m) continue;
                
                if(a + stainA < n){
                    nextStates[a + stainA] = Math.min(nextStates[a + stainA], states[a]);
                }
                if(states[a] + stainB < m){
                    nextStates[a] = Math.min(states[a] + stainB, nextStates[a]);
                }
                
            }
            states = nextStates;
            
        }
        for(int a=0;a<n;a++){
            if(states[a] < m){
                answer = Math.min(a, answer);
                break;
            }
        }
        
        if(answer == n) answer = -1;
        return answer;
    }
    
}
```

코딩할 때는 nextStates의 의미를 잘 몰랐는데 다시 보니 states가 수정되고 있으므로 어쩔 수 없다. 다만 수정되는 states는 항상 a + stainA 이거나 a이다. a 위치를 수정하는 것은 지금 보고 다시 안 볼 것이므로 의미가 없다. 만약 nextStates를 안 쓰려면 a + stainA에 최적값이 먼저 들어있어야 하므로 for문을 역순으로 조회하면 states 하나만 둬도 가능하다.
